CHAPTER 01

gstack이 도대체 뭔가요?

한 줄로: Claude Code 안에서 "전문가 역할"을 빌려 쓰는 명령어 모음입니다. Y Combinator 대표 Garry Tan이 만들었고, 오픈소스라 무료예요.

피자 가게 비유로 설명할게요.

여러분이 작은 피자 가게를 혼자 운영한다고 생각해보세요. 주방장, 배달원, 회계사, 매니저 역할을 전부 혼자 해야 한다면 너무 힘들죠.

gstack은 "오늘은 회계사 모자를 쓰세요" / "지금은 주방장처럼 생각해보세요"라고 옆에서 알려주는 모자 걸이 같은 거예요. 같은 사람(=Claude)이지만, 어떤 모자를 쓰느냐에 따라 일하는 방식이 완전히 달라집니다.

왜 다들 좋다고 하나요?

Claude Code에 그냥 "이 코드 검토해줘"라고 던지면, Claude는 어디서부터 어떻게 봐야 할지 매번 즉흥적으로 결정해요. 결과는 그때그때 달라지죠.

gstack의 /review를 쓰면, YC가 실리콘밸리에서 수천 개 스타트업을 검토하며 다듬은 체크리스트를 그대로 따라가요. 매번 같은 깊이로, 같은 항목을 빼먹지 않고요.

요리 레시피 비유:

"맛있게 해줘"라고 말하면 요리사 기분에 따라 결과가 들쭉날쭉합니다. 반면 "백종원 김치찌개 레시피로"라고 말하면, 매번 비슷한 맛이 나죠.

gstack 명령어는 검증된 레시피예요. Claude의 즉흥성을 줄이고, 결과의 일관성을 높입니다.

핵심 구성

  • 47개의 슬래시 명령어 — 각각 다른 "역할" 또는 "워크플로우"
  • 자체 브라우저 (/browse) — Playwright 기반, 웹페이지를 직접 열고 조작
  • 마크다운으로 작성된 프롬프트 모음 — 비밀 같은 거 없음, 다 열려 있음

gstack은 새로운 AI가 아닙니다. 여러분이 이미 쓰는 Claude를 더 잘 쓰는 법이에요. 비유하자면 같은 자동차에 네비게이션을 다는 것과 같습니다.

CHAPTER 02

설치는 끝났는데, 이제 뭘 해야 하죠?

좋은 소식이에요. 여러분은 이미 설치가 끝났어요. ~/.claude/skills/gstack/에 47개 명령어가 모두 들어가 있고, CLAUDE.md에도 등록됐죠.

지금 당장 작동하는지 확인하는 법

Claude Code 채팅창에 그냥 /를 한 번 쳐보세요. 자동완성 목록에 /browse, /review, /office-hours 같은 것들이 보이면 설치 완료입니다.

채팅창에 이렇게 입력해보세요:

/learn

그러면 gstack이 스스로를 가르쳐줘요. 첫 명령어로 가장 추천합니다.

새 스마트폰 비유: 박스에서 막 꺼낸 폰엔 앱이 잔뜩 깔려 있지만, 뭐가 뭔지 모르잖아요? 일단 "앱 둘러보기" 튜토리얼부터 누르는 게 자연스럽죠. /learn이 딱 그거예요.

CHAPTER 03

슬래시 명령어 — 마법 주문 사용법

슬래시 명령어는 그냥 "미리 준비된 긴 부탁"이에요. 짧게 치면 길고 정교한 부탁이 자동으로 펼쳐집니다.

편의점 도시락 비유:

"밥, 김치, 계란, 멸치볶음, 김 준비해서 도시락 만들어줘"라고 매번 말하기 귀찮죠? 그래서 편의점에선 "한식 도시락 하나요" 한 마디면 끝납니다.

슬래시 명령어가 그거예요. /review 한 마디 = "방금 바꾼 코드를 시니어 엔지니어 관점에서 보안, 성능, 가독성, 테스트 누락 순으로 검토하고 우선순위별로 정리해줘"라는 긴 부탁의 단축키.

입력 방법 3가지

방법1
그냥 명령만 — /review → Claude가 알아서 컨텍스트 잡고 진행
방법2
인자와 함께 — /browse https://naver.com → 그 URL을 열어줌
방법3
여러 줄로 — /office-hours 블로그 등급 예측 정확도 올리고 싶어 → 그 주제로 컨설팅 시작

같은 작업, 3가지 방식 비교

그냥 채팅:   "이 PR 좀 봐줘"      → 즉흥 검토
슬래시 명령: /review              → 체크리스트 검토
인자 추가:   /review 보안 위주로  → 보안 집중 검토

슬래시 명령어는 다른 명령어보다 비용이 큽니다. 명령마다 평균 3,000~15,000 토큰이 추가로 들어가요. 매번 모든 일에 /review를 붙일 필요는 없습니다. 진짜 검토가 필요할 때만 쓰세요.

전자레인지 비유: 전자레인지가 편하다고 따뜻한 물 한 컵까지 거기 돌리진 않잖아요? 슬래시 명령은 식사용이고, 일반 채팅은 음료수입니다.

CHAPTER 05

슈퍼파워스 스킬과 어떻게 합쳐 쓰나요?

두 시스템은 계층이 다릅니다. 충돌하지 않고 보완해요. 이 챕터 하나만 잘 이해해도 절반은 끝나요.

요리사 비유로 한 번에 정리:

슈퍼파워스 = "요리사의 습관". 손 씻기, 도마 닦기, 간 보기 같은 무의식적 규율. 어떤 요리를 하든 자동으로 발동됩니다.

gstack = "오늘의 메뉴 코스". "오늘은 이탈리안 풀코스", "오늘은 한정식". 큰 흐름과 역할을 결정합니다.

요리사가 한식 코스를 만들면서도 손 씻는 습관은 그대로 유지하죠. 두 시스템이 같이 돌아가는 방식이 정확히 이거예요.

표로 비교

구분슈퍼파워스gstack
역할방법론 (HOW)워크플로우 (WHAT)
예시TDD, 브레인스토밍, 디버깅 절차"PR 리뷰해", "QA 돌려"
발동 방식자동 (상황 인식)명시적 (/명령)
주 효과코드 작성 규율역할 / 페르소나

융합 시나리오

1
/office-hours 입력 → gstack이 YC 파트너 페르소나 활성화 → 그 안에서 슈퍼파워스 brainstorming 스킬이 자동 발동해서 6개 질문이 더 깊어짐
2
코드 작성 단계 → 슈퍼파워스 TDD 스킬이 자동 발동, "테스트 먼저 작성하세요"라고 가이드
3
/review 입력 → gstack의 시니어 엔지니어 페르소나 + 슈퍼파워스의 코드 분석 규율이 동시 발동

축구팀 비유: gstack은 포지션(공격수, 수비수, 골키퍼) 같은 거고, 슈퍼파워스는 기본기(트래핑, 패스, 시야 확보) 같은 거예요. 공격수가 됐다고 기본기를 잊는 게 아니죠. 둘은 동시에 돌아갑니다.

두 시스템의 충돌이 걱정될 때는 사용자 지시가 항상 한 수 위입니다. CLAUDE.md에 "TDD 쓰지 마세요"라고 적혀 있으면, gstack 명령도 그 규칙을 존중합니다. 사용자 지시 > 슈퍼파워스 > gstack 우선순위예요.

CHAPTER 06

실전 시나리오 — 내 프로젝트에 적용하기

여러분의 blog_grade_collector 프로젝트를 기준으로 가장 자연스러운 활용 시나리오 3가지를 보여드릴게요.

시나리오 1 — Mode B 정확도 60% 돌파 아이디어 정리

1
/office-hours 외부 블로그 예측이 57%에서 안 올라감 — Claude가 YC 파트너처럼 "데이터 라벨링이 진짜 문제냐?", "지금 측정 지표가 맞냐?"라고 캐물어요.
2
/autoplan — 정리된 아이디어를 단계별 계획서로 저장. 코드는 안 짭니다.
3
/plan-eng-review — "이 계획의 약점은?" 시니어 엔지니어 관점 검토
4
실제 구현 (슈퍼파워스 TDD가 자동 가이드)
5
/review → /ship — 검토하고 배포

시나리오 2 — 서버에서 place.service 502 났을 때

1
/investigate place.service 502 났음, naver_place_server.py 최근 변경 후 발생
2
Claude가 체계적으로: 로그 확인 → 최근 커밋 → 의심 함수 → 가설 → 검증 순으로 분석
3
근본 원인 파악 후 패치 → /review → 배포

그냥 "502 났어 고쳐줘"라고 하면 Claude가 즉흥적으로 추측합니다.

/investigate를 쓰면 가설을 세우고 → 증거를 모으고 → 검증하는 정찰 절차를 거쳐요. 결과적으로 엉뚱한 곳을 고치는 일이 줄어듭니다.

시나리오 3 — 네이버 블로그 페이지 직접 검증

1
/browse https://m.blog.naver.com/buanaes
2
스크린샷 + DOM + 콘솔 로그까지 한 번에 받아옴
3
INITIAL_STATE 파싱 결과가 코드와 일치하는지 즉시 확인 가능

군대 정찰 비유: /investigate는 정찰병이에요. 무작정 돌격(=즉흥 디버깅)하기 전에 적의 위치, 무기, 약점을 파악하고 옵니다. 시간이 더 걸리는 것 같지만, 결국 훨씬 빨라요.

CHAPTER 08

자주 묻는 질문

초보들이 흔히 막히는 지점들이에요.

Q1. 슬래시 명령어가 자동완성에 안 떠요

Claude Code를 재시작해보세요. 그래도 안 되면 ~/.claude/skills/gstack/ 폴더가 있는지 확인하고, 거기서 ./setup을 다시 실행하세요.

Q2. /browse가 페이지를 못 열어요

Windows에서는 Playwright Chromium이 따로 설치되어야 해요. bunx playwright install chromium을 한 번 실행해보세요.

Q3. /review 결과가 너무 길어요

구체적인 범위를 알려주면 짧아집니다. /review naver_place_server.py의 _shape_grade_for_frontend 함수만 같이요.

Q4. 모든 작업에 슬래시 명령을 써야 하나요?

아뇨, 절대 그러지 마세요. 슬래시 명령은 비용이 큰 무거운 도구입니다. 간단한 질문은 그냥 채팅으로 하시고, "검토 / 계획 / 리뷰 / QA" 같은 무거운 작업에만 쓰세요.

택시 비유: 길 건너편 편의점도 택시 타고 가진 않잖아요? 슬래시 명령은 먼 거리 갈 때 부르는 택시입니다. 가까운 거리는 그냥 걸어가세요.

Q5. 슈퍼파워스만 써도 충분하지 않나요?

슈퍼파워스는 "잘 만드는 법"을 가르쳐요. gstack은 "무엇을 만들지 결정하는 법"을 도와줍니다. 둘 다 다른 층위라 같이 쓰면 가장 강력해요.

Q6. 비용이 너무 늘어나면 어떡하죠?

슬래시 명령 한 번에 평균 3K~15K 토큰 추가입니다. 하루에 5번 쓰면 무시할 수준이지만, 자동 루프에 넣으면 폭증할 수 있어요. 의식적으로 사용하세요.

Q7. 명령어를 내가 만들 수도 있나요?

네. gstack 명령어는 다 마크다운 파일이에요. ~/.claude/skills/gstack/<명령이름>/SKILL.md를 열어보면 그냥 잘 짜여진 프롬프트 모음입니다. 복붙해서 본인 버전을 만들 수 있어요.

레시피북 비유: 백종원 레시피북을 갖고 있다고 새 요리 못 만드는 거 아니죠. 보고 배운 다음 "내 집 김치찌개 레시피"를 적어두면 그게 본인 가족의 표준이 됩니다. gstack 명령어도 똑같이 응용 가능해요.

gstack은 새로운 기술이 아니라 새로운 습관입니다. 일주일만 의식적으로 써보면, 그 다음부턴 자연스럽게 손이 갑니다. 부담 갖지 말고 천천히, 명령 하나씩 친해져 보세요.
