# EPL 승부예측 게임 — 예준이용 가이드

## 1. 이 앱이 뭐야?

EPL(잉글랜드 프로축구) 2024-25 시즌 **실제 경기 20개**의 결과를 예측하고, 맞힌 개수로 점수를 매겨 친구들과 겨루는 웹 게임이야.
경기 하나를 맞힐 때마다 3점, 총 20경기라서 만점은 60점.
서버 없이 **HTML 파일을 브라우저로 여는 것만으로** 돌아가.

## 2. 실행 방법

`index.html` 파일을 **더블클릭**하면 크롬(또는 아무 브라우저)에서 바로 열려. 설치·서버 필요 없음.

## 3. 파일 4개가 각각 하는 일

| 파일 | 하는 일 | 비유 |
|------|---------|------|
| `index.html` | 화면의 뼈대(제목, 입력칸, 버튼, 표) | 집의 **골조** |
| `style.css` | 색·글씨·간격·애니메이션 | 집의 **인테리어** |
| `data.js` | EPL 경기 20개(팀·날짜·스코어) + 팀별 시즌 순위 | 게임의 **문제은행** |
| `app.js` | 예측 저장·채점·상세결과·랭킹 | 게임의 **두뇌** |

## 4. 게임 흐름

> **예측의 근거 — "지난 경기인데 뭘 예측하지?"**
> 결과는 이미 나왔지만, 플레이어가 그 결과를 모른다는 전제로 **각 팀의 2024-25 시즌 최종 순위**를 근거로 승패를 추론하는 게임이야. "1위 리버풀(홈) vs 4위 첼시 → 홈승 유력" 같은 식.
> 지난 경기를 쓴 이유는 **즉시 채점**이 가능하고 openfootball 실데이터로 검증할 수 있어서야. 진짜 서비스라면 아직 안 끝난 미래 경기를 예측하고 결과가 나온 뒤 채점하겠지 — 이 트레이드오프를 발표 때 설명하면 좋아.

1. **이름 입력** → 게임 시작
2. **경기 20개** 각각 두 팀의 순위를 보고 [홈 승 / 무승부 / 원정 승] 중 하나 선택 (몇 개 골랐는지 진행 표시)
3. 20개 다 고르면 **채점하기** 버튼이 켜짐
4. 채점 결과:
   - 내 점수 + **백분율** (예: 30 / 60점 · 50%)
   - **경기별 상세**: "내 예측 vs 실제 결과 (스코어) ⭕/❌"
   - **랭킹** (내 줄은 노란색으로 강조)

## 5. 따라 만들기 순서 (빈 폴더에서 시작)

한 번에 다 만들지 말고, 단계마다 브라우저를 새로고침해서 "뭐가 보이는지" 확인하면서 가.

**1단계 — data.js (경기 데이터)**
경기 하나는 이렇게 생겼어:
```js
{ home: "토트넘", away: "에버턴", date: "2024-09-14", homeScore: 4, awayScore: 0 }
```
이런 걸 `MATCHES` 배열에 20개 넣으면 끝.
→ *여기까지 하면*: 화면엔 아무것도 안 보여. 데이터만 준비된 상태.

**2단계 — index.html + style.css (화면)**
제목, 이름 입력칸, "게임 시작" 버튼, 그리고 나중에 채워질 빈 공간(`match-list`)을 만들어.
→ *여기까지 하면*: 제목과 이름 입력칸이 보여. 버튼을 눌러도 아직 아무 일 없음.

**3단계 — app.js 앞부분 (시작 + 경기 카드 + 선택)**
"게임 시작"을 누르면 경기 카드 20개를 그리고, 버튼을 누르면 예측을 기억하게 만들어.
→ *여기까지 하면*: 경기 20개가 뜨고 예측을 고를 수 있어. 다 고르면 채점 버튼이 켜져.

**4단계 — app.js 뒷부분 (채점 + 상세 + 랭킹)**
채점 버튼을 누르면 예측과 실제 결과를 비교해 점수를 매기고, 경기별 상세와 랭킹을 보여줘.
→ *여기까지 하면*: 게임 완성!

## 7. 보안 과제 — "점수 조작 막기" (제출 핵심)

이 게임은 **정답·채점·저장이 전부 내 브라우저 안에서** 일어나. 그래서 조작 경로가 3가지나 있어. 하나씩 이해하는 게 이 과제의 핵심이야.

### 조작 경로 3단계

| # | 조작 방법 | 왜 가능한가 |
|---|----------|-------------|
| 1 | **정답을 미리 본다** — F12 → `data.js`의 `homeScore/awayScore`를 읽고 정답만 찍으면 60점 만점 | 정답이 브라우저에 실려 있음 |
| 2 | **채점을 조작한다** — 채점 코드가 브라우저에서 돌아서 `score` 변수를 바꿀 수 있음 | 채점이 클라이언트에서 실행됨 |
| 3 | **점수를 직접 바꾼다** — localStorage의 점수를 999로 수정 | 저장이 사용자 컴퓨터에 있음 |

가장 근본적인 건 **1번**이야. 채점을 아무리 잘 짜도, 정답이 브라우저에 있으면 소용없어.

### 내가 시도한 방어 (그리고 그 한계)

`app.js`에 **점수 검증**을 넣었어: 점수가 0~60 사이의 3의 배수가 아니면 랭킹에 "⚠️검증실패"로 표시돼.

직접 해보자 (F12 → Console):
```js
// 순진한 조작 → 검증에 걸림 (⚠️검증실패)
localStorage.setItem("rankings", JSON.stringify([{name:"해커", score:999}]))
```
```js
// 영리한 조작 → 검증 통과 (못 막음!)
localStorage.setItem("rankings", JSON.stringify([{name:"영리한해커", score:60}]))
```
→ 한 판 플레이하면 랭킹에서 결과 확인.

**여기서 배우는 것**: 클라이언트 검증은 *순진한 조작*은 막지만, 규칙을 아는 사람의 *영리한 조작(60점처럼 유효한 값)*은 절대 못 막아.

### 진짜 해결책

- 정답은 **서버에만** 둔다 (브라우저로 안 보냄).
- 채점도 **서버에서** 한다.
- 브라우저는 **예측만** 서버로 보낸다.
- 그러면 점수를 바꿔도 서버가 다시 계산하니까 조작이 안 통해.

### 보너스: XSS도 막았어

이름을 랭킹에 표시할 때 `innerHTML` 대신 `textContent`를 썼어. 안 그러면 이름칸에 `<script>`를 넣어 다른 사람 브라우저에서 코드를 실행시키는 공격(XSS)이 가능하거든. (`app.js` 랭킹 렌더링 부분 주석 참고)
