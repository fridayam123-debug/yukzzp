# 롤링페이퍼: 전승기 강사님 응원 메시지

## 목적
첫 강의를 성공적으로 마친 전승기 강사님께 수강생(약 60명)들이 익명 응원·감사 메시지를 남기는 웹페이지. 서버/빌드 없이 `index.html`을 더블클릭해서 바로 열 수 있어야 하며, Supabase를 통해 메시지가 새로고침 후에도 유지되고 링크를 공유받은 다른 사람도 같은 메시지 목록을 볼 수 있어야 한다.

**(2026-07-26 추가 수정: 이름 입력 완전 삭제 — 전원 익명 작성 / 수강생 정원에 맞춰 최대 60개 메시지로 제한 / 초기 시드 메시지 제거하고 실제 수강생 작성분만 표시)**

## 카피
**(2026-07-26 최종 수정)**
- 제목: "전승기 강사님의 첫 강의 잊지 않겠습니다"
- 부제: "전승기를 만나면 전성기가 옵니다."
- 안내문: "첫 강의를 함께한 마음을 남겨주세요."
- 바이라인: "from. 전성기를 준비하는 사람들"

## 파일 구조
- 새 독립 폴더 `rolling-paper/` (기존 Next.js 레스토랑 프로젝트와 무관한 별개 산출물이므로 루트에 분리)
- `rolling-paper/index.html` — 진입점, 더블클릭으로 실행
- `rolling-paper/style.css` — 스타일
- `rolling-paper/app.js` — Supabase 연동 및 렌더 로직
- Supabase JS는 CDN(`https://cdn.jsdelivr.net/npm/@supabase/supabase-js@2`)으로 로드. 빌드 도구 없음.
- `app.js` 상단에 `SUPABASE_URL`, `SUPABASE_ANON_KEY` 상수로 분리 — Supabase 프로젝트 생성 후 값만 교체하면 됨.

## 데이터 모델 (Supabase)
**(2026-07-26 추가: 본인 글 삭제 기능 + 욕설 필터)**

테이블 `messages`:
| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | uuid, PK, default gen_random_uuid() | |
| message | text, not null | |
| created_at | timestamptz, default now() | |
| secret | text, nullable | 삭제 권한 확인용 랜덤 토큰. 작성자 브라우저의 localStorage에만 저장, 목록 조회 응답에는 포함하지 않아 다른 사람에게 노출 안 됨 |

이름 컬럼 없음 — 전원 익명 작성이라 저장하지 않음.

RLS: anon 키로 insert/select/delete 가능하도록 정책 설정 (공개 롤링페이퍼이므로 인증 없이 열람/작성/삭제 허용).
DB 트리거로 총 60개 초과 insert를 거부 (수강생 정원과 동일하게 제한, 클라이언트 우회로도 뚫리지 않도록 서버 측에서 강제).
DB 트리거로 욕설/비속어 목록에 해당하는 메시지 insert를 거부 (클라이언트 필터와 별개로 서버에서도 강제).

**보안 관련 참고**: delete RLS 정책은 `using (true)`로 열려 있고, 실제 삭제 보호는 앱 코드가 `id`와 `secret`을 함께 조건으로 거는 것에 의존한다. `secret`이 목록 조회에 노출되지 않아 일반적인 사용에서는 본인 글만 삭제되지만, anon key로 직접 API를 호출하는 기술적 우회까지는 막지 못한다. 60명 규모의 비공개 링크 공유라는 낮은 위협 수준에 맞춘 실용적 절충.

## 데이터 흐름
**(2026-07-26 변경: 최신순 → 등록순. 1번째 마음이 맨 위, 새 글은 맨 아래에 추가)**
1. 페이지 로드 → `messages` 테이블을 `created_at` 오름차순(등록순)으로 전체 조회 → 카드 그리드로 렌더. 각 카드에 "N번째 마음" 순번 라벨 표시
2. 사용자가 메시지(필수) 입력 후 등록 버튼 클릭 → Supabase insert
3. insert 성공 시: 폼 초기화 + 새 카드를 목록 맨 아래(다음 순번)에 fade-in으로 추가 (재조회 없이 로컬 append). 본인 글 삭제 시 남은 카드 순번을 1번부터 다시 매김
4. 실시간 동기화(다른 사용자의 새 메시지가 새로고침 없이 반영)는 범위 밖 — 새로고침 시 최신 목록이 보이는 것으로 충분

## 화면 구성
레퍼런스 구조(레이아웃만 차용, 컬러는 블랙+크림 유지):

- **히어로**: 작은 상단 라벨(대문자 트래킹) + 큰 볼드 타이틀 "전승기 강사님, 축하합니다!" + 서브텍스트 "전승기를 만나면 전성기가 옵니다!!" + 안내문 "따뜻한 한마디를 남겨보세요"
- **입력 폼 카드** (블랙 보더 박스):
  - 좌측 상단 라벨 "FROM. 익명의 마음"
  - 섹션 타이틀(볼드) "응원 메시지 남기기"
  - 메시지 필드: label "응원 한마디" + 우측 글자수 카운터 "0/200" (최대 200자, 2026-07-26 300→200 축소), placeholder "따뜻한 한마디를 남겨주세요..." — 이름 입력 없음(전원 익명)
  - 등록 버튼 (60개 도달 시 "정원이 가득 찼습니다"로 비활성화)
  - 하단 안내문: "욕설·비방·광고성 내용은 등록이 제한됩니다. 등록한 메시지는 카드의 × 버튼으로 본인만 삭제할 수 있어요."
- **메시지 월 섹션**:
  - 좌측 라벨 "TO. 전승기 강사님께"
  - 섹션 타이틀(볼드) "도착한 마음들"
  - 우측 카운트 뱃지 "N개의 마음" (N = 현재 메시지 수, 최대 60)
  - 카드 그리드(반응형 2~3열, 모바일 1열). 각 카드: 메시지 텍스트 + 점선 구분선 + "N번째 마음" 순번 라벨(좌) / 날짜(우) — from/이름 표시 없음
  - 본인이 작성한 카드에는 우측 상단에 작은 × 삭제 버튼 표시(다른 사람 글에는 안 보임). 클릭 시 confirm 확인 후 삭제, 빈 자리는 즉시 목록에서 제거되고 카운트도 갱신
- **빈 상태 / 페이퍼 채우기 방식** (2026-07-26 확정): 화면에는 항상 최소 4장의 페이퍼가 보임. 메시지 0개면 빈 종이 4장(글씨 없음, 종이 질감만). 수강생이 작성할 때마다 빈 종이 한 장이 실제 메시지로 채워지고(총 4장 유지), 실제 메시지가 4개를 넘어서면 작성되는 대로 페이퍼가 추가 생성됨(최대 60장). 본인 글 삭제 시에도 4장 미만으로 떨어지면 빈 종이로 다시 채움. (Supabase 연결 실패 등 진짜 에러 상황은 텍스트 안내 박스 사용)

## 비주얼 디자인
**(2026-07-26 수정: 블랙+크림 에디토리얼 → 핑크 톤 + 찢어진 종이(torn paper) 느낌으로 최종 변경)**

레퍼런스: 연핑크 줄노트 배경 위에 찢어진 종이 질감 카드(VISION/GOALS 스타일)

- **배경**: 소프트 핑크(`#F8D9E6` 톤) + 얇은 대각선 줄무늬(줄노트 느낌, CSS `repeating-linear-gradient`로 구현 — 이미지 에셋 불필요)
- **카드/종이**: 웜 오프화이트(`#FBF7EF`) 종이색. `clip-path`로 사방(상하좌우)에 미세한 톱니 포인트(50개+)를 촘촘히 넣어 거친 지그재그 대신 정교하고 부드러운 찢김 실루엣 표현 + `filter: drop-shadow`로 종이가 뜬 듯한 그림자. 크리스(접힌 자국)는 하드한 대각선 대신 부드러운 radial-gradient 얼룩 4개 + 미세 그레인으로 표현(2026-07-26 정교화). 카드마다 약간의 회전(-1.5deg~1.5deg 교차)으로 손으로 놓은 듯한 배치
- **텍스트**: 헤드라인은 딥 네이비(`#232759` 톤, 레퍼런스의 VISION/GOALS 글자색과 동일 계열), 본문은 소프트 네이비 그레이(`#4B4F73`)
- **장식**: 나비·반짝임 낙서 모티프를 절제된 형태(얇은 라인 SVG, 1~2개)로 히어로 영역에만 소량 배치 — 레퍼런스처럼 과하게 흩뿌리지 않음
- **타이포그래피**: [Pretendard](https://cdn.jsdelivr.net/gh/orioncactus/pretendard/dist/web/static/pretendard.css) 유지. 헤드라인 Bold(700), 본문 Regular(400)~Medium(500)
- **입력 폼 카드**: 라운드 코너 화이트/오프화이트 카드 + 소프트 그림자로 통일감 유지 (찢어진 모양은 메시지 카드에만 적용)

## 반응형 & 접근성
- **브레이크포인트**: 모바일(<640px) 카드 1열, 태블릿(640~1024px) 2열, 데스크톱(>1024px) 3열
- **터치 타겟**: 버튼·입력창 높이 최소 44px
- **입력 폰트 크기**: 모바일 자동 확대(zoom) 방지 위해 input/textarea `font-size` 16px 이상
- **포커스 표시**: 블랙 보더 톤에 맞춰 탭 이동 시 명확한 포커스 아웃라인(2px solid) 유지 — 제거 금지
- **대비**: 블랙 텍스트 on 크림 배경으로 WCAG AA 기준(4.5:1) 자연 충족
- **라벨**: 이름/메시지 입력창은 placeholder가 아닌 실제 `<label>` 사용 (플레이스홀더만으로 라벨 대체 금지)

## 에러 처리
- 메시지가 빈 값이면 등록 버튼 클릭 시 제출 차단 + 인라인 안내
- 메시지는 최대 200자 — textarea `maxlength=200` + 실시간 글자수 카운터로 초과 입력 자체를 막음
- 60개 도달 시: 등록 버튼 비활성화 + "정원이 가득 찼습니다" 표시. DB 트리거가 서버 측에서도 강제 거부(클라이언트 우회 방지)
- 욕설/비속어 목록에 해당하는 내용 입력 시: "부적절한 표현이 포함되어 있어 등록할 수 없습니다" 표시. 클라이언트 1차 필터 + DB 트리거 2차 강제
- 삭제 실패 시(네트워크 오류 등): "삭제에 실패했습니다. 다시 시도해주세요." 알림
- Supabase 연결/insert 실패 시 화면에 에러 메시지 노출 (예: "메시지 등록에 실패했습니다. 다시 시도해주세요.")
- 최초 조회 실패 시(네트워크 문제 등) 안내 문구 표시

## 테스트 방법
- 로컬에서 `index.html` 직접 열어 등록 → 새로고침 → 메시지 유지 확인
- 두 개의 브라우저 탭(또는 다른 브라우저)에서 각각 열어, 한쪽에서 등록한 메시지가 다른 쪽 새로고침 후 보이는지 확인 (공유 시나리오 검증)
- 빈 메시지로 등록 시도 시 차단되는지 확인
- 60개 등록 후 추가 등록 시도 시 차단되는지 확인 (버튼 비활성화 + DB 트리거)

## 배포 및 설치
- 순수 정적 파일(서버·env 불필요, Supabase URL/anon key는 공개 가능한 클라이언트 키라 코드에 직접 포함)이므로 Netlify Drop(`netlify.com/drop`)에 `rolling-paper/` 폴더를 드래그하는 것만으로 배포 가능
